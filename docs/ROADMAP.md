# 実装ロードマップ

設計 ([DESIGN.md](./DESIGN.md)) を段階的に実装するための計画。
各マイルストーンは**それ単体で動作を確認できる**単位に切ってある。

---

## M0 — 土台

**目標**: 空のプロジェクトが `npm run dev` で起動し、CI が通る。

- [ ] electron-vite + TypeScript(strict) + ESLint/Prettier の雛形
- [ ] `src/shared/types` と `src/shared/ipc/channels.ts` の骨組み
- [ ] `Clock` / `Rng` インターフェース（DESIGN.md §16 のテスト決定論化の前提）
- [ ] Vitest 設定、GitHub Actions（lint + typecheck + unit）
- [ ] electron-builder 設定（NSIS + portable、未署名）
- [ ] パック整合性チェックスクリプト（`npm run check:packs`）— 検証 V1–V12 のうち静的に効くものを CI で回す

**完了条件**: 何も表示されないが常駐し、トレイから終了できる。

---

## M1 — 見えるようにする

**目標**: 透過オーバーレイにキャラが立ち、クリックが背後に抜ける。

- [ ] `OverlayWindowManager`: ディスプレイ毎の透過・クリックスルー窓（DESIGN.md §5.1）
- [ ] PixiJS 初期化、`AnimationPlayer`
- [ ] `PackManager` + zod スキーマ + `AlphaMaskBuilder`（読込時のマスク事前展開）
- [ ] `HitTester`（per-pixel + ヒステリシス、DESIGN.md §5.3）
- [ ] **ルナの作画**: 46 フレーム（`packs/luna/sprites/README.md` 参照）
- [ ] 適応フレームレート（§6.3）

**完了条件**: ルナが `idle` で待機し、体の上でだけカーソルが効く。透明部分のクリックは背後のアプリに通る。

**リスク**: ここが最も環境差が出る。GPU ちらつきの検証を複数マシンで行うこと。

---

## M2 — 動く・掴める

**目標**: 生き物らしく振る舞い、ドラッグして投げられる。

- [ ] `BehaviorFSM`（重み付き遷移、優先度調停、DESIGN.md §7.1–7.2）
- [ ] `Physics`（固定タイムステップ、重力・反発・摩擦、§8）
- [ ] `SurfaceMap`（作業領域下端のみ。ウィンドウ乗りは M4）
- [ ] `DragController`（投げ速度のサンプリング、ポインタキャプチャ）
- [ ] `TrayController` と最小限のメニュー（呼ぶ / 隠す / 終了）
- [ ] マルチディスプレイの Actor Handoff（§4.1）

**完了条件**: 歩き、座り、寝る。掴んで投げるとタスクバーの上に着地する。2 画面を跨いで歩ける。

---

## M3 — 状況に反応する

**目標**: 本アプリの差別化点を入れる。

- [ ] `SensorHub` + 各ソース（CPU / メモリ / バッテリ / 時刻 / 無操作 / セッション / ネットワーク）
- [ ] `Normalizer`（EMA・シュミットトリガ・エッジ検出、§9.2）
- [ ] `ReactionEngine` + 条件 DSL 評価器
- [ ] `Governor`（クールダウン・発話上限・静音モード、§9.3）
- [ ] `SpeechBubble`（DOM 層、文字送り、画面端反転）
- [ ] `dialogue` のプレースホルダ展開

**完了条件**: CPU を張り付かせると汗をかいて喋る。放置して戻ると「おかえり」と言う。1 時間の発話が 6 回を超えない。

**この段階で必ず「1 日使ってみる」こと。** うるささの調整は実測でしかできない。

---

## M4 — Windows と仲良くする

**目標**: 他のウィンドウを認識し、邪魔をしない。

- [ ] `Win32Bridge`（koffi: `EnumWindows` / `GetWindowRect` / `GetForegroundWindow` / `GetWindowLong`）
- [ ] `ForegroundWatcher` + アプリカテゴリ分類
- [ ] 全画面アプリ検出と自動退避（§7.4）
- [ ] ウィンドウのタイトルバーに乗る / 端をよじ登る / ぶら下がる
- [ ] ウィンドウ消失時の落下
- [ ] `app.changed` / `app.fullscreen` シグナルの配線

**完了条件**: エディタのタイトルバーに座り、その窓を閉じると落ちる。ゲームを全画面で起動すると消え、終了で戻る。

**リスク**: koffi の呼出でアンチウイルス誤検知の可能性。この機能群は設定で丸ごと OFF にでき、OFF でも M0–M3 の全機能が動くように分離しておく。

## M6 以降 — 任意

優先度順に並べるが、いずれも M5 の品質を落としてまで入れない。

| 案 | 概要 | 備考 |

| 自動更新 | electron-updater | 署名が前提 |

## 進め方の原則

1. **M1 のクリックスルーが本プロジェクト最大の技術リスク**。ここを最初に潰す。
   動かないと分かった場合、この時点なら方式変更（小窓移動方式への退避）の傷が浅い。
2. 各マイルストーンの完了条件は**実機で目視確認**する。ユニットテストは通っても体験は分からない。
3. M3 完了後に一度立ち止まり、自分で常用して「うるさくないか」を確認する。
   ここで妥協すると、機能を足すほど嫌われるアプリになる。
